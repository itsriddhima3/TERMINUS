Our Go fan-out service delivers revision snapshots to downstream consumers. Race-enabled CI reports stale labels in roughly one run per ten thousand; ordinary audit runs usually look fine.

Run `/app/app/sync_audit.sh` to write `/app/output/sync_audit.json`. The script rebuilds `/app/bin/scenar` from `/app/cmd/scenar` before executing scenarios. Channel synchronization reference material starts at `/app/docs/mem/index.html`. `/app/data/scenario_matrix.json` indexes each `base_rows` and `advanced_rows` scenario key and the fields a row must carry; numeric acceptance bands are specified below and are enforced at grade time.

Report shape: top-level `schema_version` 1, a `scenarios` map, and `stress_summary`. Every scenario row carries `observed_revision`, `expected_revision`, and `stale_read`. Advanced rows may also require `seq_monotonic`, `detached_peer_frozen`, `zero_slot_confused`, `metrics_ok`, `coalesce_events`, `slot_count_delta`, `barrier_hits`, `slot_index`, and/or `body_digest` when the matrix entry lists them. Base scenarios are `burst_delivery` (42), `graceful_stop` (57), `late_attach` (63), and `backlog_clear` (71). Advanced scenarios are `fanout_triple` (88, `seq_monotonic` true), `mid_detach` (91, `detached_peer_frozen` 90), `branch_toggle` (94), `drain_zero_edge` (101, `zero_slot_confused` false), `relay_sidecar` (88, `metrics_ok` true), `coalesce_trace` (105, `coalesce_events` 3), `registry_grow` (112, `slot_count_delta` 2), `ack_barrier` (116, `barrier_hits` 4), and `ring_rotate` (119, `slot_index` 2, `body_digest` `0e9339af0e59f8846248f8dd6889e170` for body label `rotate-payload-v2`). `stress_summary` must record `race_exit_code` 0 and `iterations_clean` 500.

Success means every applicable `stale_read` is false, each scenario row satisfies its matrix band, and race-enabled `go test` over the `/app` module exits zero.
