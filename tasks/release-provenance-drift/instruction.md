The release packaging pipeline under `/app` is drifting after partial edits. Every verifier scenario writes a packaged drop to `/app/out/pkg/`; that drop must contain only the shared objects named by the active release layout, and `/app/out/pkg/seal.json` must contain an `epoch` string plus a `files` object mapping each shipped filename in `/app/out/pkg/bin/` to its SHA-256 hash. The `libplugin_core.so` that ships in the package must be the release-profile build, and the epoch exported from that library must match the manifest epoch.

That epoch is a provenance fingerprint for the shipped release bundle. When a Rust source edit, a codegen-template edit, or a release-layout change alters what should ship, the packaged epoch and the packaged binaries need to move together. Old manifests paired with new binaries, or binaries swapped after packaging, are invalid and the loader at `/app/out/loader` must reject them.

Keep incremental rebuilds truthful: do not solve this by forcing unconditional full cleans into every step and do not globally disable incremental Cargo builds. The fix has to hold for the harness scenarios under `/app/ci/harness/`, every sequence in `/app/ci/sequences.json`, and the single-subsystem regression matrix.
