The DOT layout chainwalk audit pipeline under `/app` sweeps bundled staging packs and should emit a JSON verdict bundle plus colorized marked layout copies.

Staging audits bundled handoff material under `/app/cases/` (layout sketches plus credential blobs under `/app/cases/<pack_id>/certs/`). QA reports verdict drift on repeat sweeps: deny-ledger identities paint cleared routes, validity windows that have not opened yet read as live, three-level chains report OK from the trust verifier with the untrusted stack wired backwards, and some layouts whose header severs a handoff link finish with process exit status zero. A sketch that only connects a service row to its credential material through a service hop never reaches the anchor; downstream trust hops look fine in isolation. Wall-clock comparisons drift against the registry TZ basis in `/app/config/runtime.env`.

Repair the audit pipeline, run `bash /app/platform/run_cases.sh` (see `/app/docs/operations.md`), write `/app/output/verdict_bundle.json`, and leave colorized layout copies under `/app/output/marked/`. Non-zero exit for any case recording a failed handoff at sweep end. The bundle must include a 16-character `run_id`, a `packs` array, and aggregate `failed_packs` / `failed_pack_ids`; any pack with a blocked deny-ledger row must list that pack id in `failed_pack_ids`. Row-level verdict fields and paint tokens are defined in `/app/docs/bundle_schema.md` and `/app/docs/style_legend.md`. Edge-family rules, trust verification wiring, and audit clock semantics are in `/app/docs/`.
