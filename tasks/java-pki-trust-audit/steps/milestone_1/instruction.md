The Java trust audit CLI under `/app` should produce `/app/output/corpus_index.json` from the PEM corpora and `/app/data/cases/case_matrix.json`, but indexed chains no longer match what operators see in the field. Several rows pick up unrelated CNs from parallel branches, report broken authority/subject key binding, or set `chain_ok` when a required signer never appeared in the bundle.

The output is a JSON object with top-level `schema_version` (integer `1`) and a `cases` array. Each case row carries `case_id`, `chain_cn`, `chain_ok`, and `aki_link_ok`. The `chain_cn` list runs in issuance order from trust anchor through to leaf. PEM bundles may include certificates from parallel branches; `chain_cn` follows only the issuer walk and must exclude those off-path CNs.

For `valid_chain`, `pem_fork_noise`, and `dual_crl_supersede`, `chain_cn` is `bench-root-live`, `bench-int-clean`, `bench-leaf-valid` with `chain_ok` and `aki_link_ok` true (`pem_fork_noise` must not list `bench-int-alt` or `bench-leaf-alt`). For `missing_link`, the required signer is absent: `chain_ok` is `false` and `chain_cn` is `[]`. For `expired_intermediate`, `chain_cn` is `bench-root-live`, `bench-int-stale`, `bench-leaf-stale-int` with `chain_ok` and `aki_link_ok` true. For `not_yet_valid_leaf`, `chain_cn` is `bench-root-live`, `bench-int-clean`, `bench-leaf-future` with `chain_ok` and `aki_link_ok` true. For `revoked_intermediate`, `chain_cn` is `bench-root-live`, `bench-int-revoked`, `bench-leaf-revoked-int` with `chain_ok` and `aki_link_ok` true. On `path_too_deep`, `chain_cn` walks from `bench-root-live` through `bench-int-clean`, `bench-int-extra`, and `bench-int-deep2` to `bench-leaf-deep`; `chain_ok` is `false` when the walk exceeds the bench path-length cap while `aki_link_ok` stays true.

Bench precedence is in `/app/docs/bench_precedence.md`; normative chain rules are in the long-form dossier under `/app/docs/pki_ops_dossier/`, not the legacy CRL notes in `/app/docs/crl_merge_notes.md`.
